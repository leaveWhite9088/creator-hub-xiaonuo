# 开发需求说明：林澈的个人顾问主页与选型排期工作台

帮我把个人顾问主页与项目选型排期工作台的前端界面做出来。我希望潜在合作方找我深聊之前，能在这个页面上读到我的技术复盘长文、横向比较我做过的代表方案、结合我的近期档期自己试算合作阶段与预算，确认意向后直接在线提交合作咨询单。

我叫林澈，常驻杭州，目前是一名独立 AI 应用研究者与工程落地顾问。以前在互联网研发团队做过两年大模型应用工程化，出来单干后主要做三件事：帮中小技术团队搭评测回归体系、做复杂智能体状态流共创，以及写一些私网离线研究工具和一线实测手记。

在视觉气质上，我希望页面**干净耐看、有现代编辑阅读感与克制的专业工具秩序感**（不要做成简陋粗糙的后台管理表，也别搞花里胡哨的霓虹特效），深浅两套配色在电脑宽屏和手机小屏上都要舒服好读。

## 一、后端数据联调与核心业务场景

我的同事已经把个人简介、代表项目档案、技术复盘手记、14 周忙闲档期日历、预算测算逻辑以及合作咨询提交接口封装在了同目录的本地模拟服务 `mock_backend.js`（全局 `window.LincheMockAPI`）里。

请直接对接这套异步接口开发前端界面（**严禁修改或覆盖 `mock_backend.js`，也不要把后端数据硬编码抄写到前端文件里绕过接口**）。它模拟了真实线上服务的异步响应延迟与偶发网关繁忙、参数拒绝等情况，接口出入参定义见同目录 `CONTRACT.md`。

页面需要打通以下五块日常业务场景：

1. **代表项目浏览、筛选与多维横向对比**
   - 展示接口返回的代表项目，支持按业务方向筛选、收藏管理（含只看已收藏）以及列表排序切换。
   - 支持把感兴趣的多份项目加入对比篮（最多同时对比 3 份），打开横向对比视图并排查看方案差异，并在无外部图表库的前提下用原生 `<svg>` 把各项目的量化能力维度直观画出来。

2. **实测手记沉浸阅读与链接分享**
   - 展示技术复盘长文列表，点开可阅读完整正文（妥善呈现小标题、列表、引用、代码片段与数据对比表格），支持章节目录跳转、上下篇切换及返回列表。
   - 无论在详情页刷新浏览器、把当前地址复制到新窗口打开，还是连续使用浏览器的后退与前进按钮，页面内容与列表上下文都应保持一致。

3. **跨内容搜索**
   - 提供统一搜索入口，支持检索项目与长文（访客常输入单个词或用空格分隔多个词查找正文里的具体技术细节）。

4. **合作范围、阶段排期与预算测算**
   - 根据接口提供的合作模式、可选交付模块、业务规模档位与期望启动周次，实时异步测算总周期、参考预算区间与分阶段里程碑。
   - 我的档期表里部分周次已有存量客户工作占用——如果访客选定的启动周加上项目持续周数撞上了忙碌周次，请在规划台里直观说明冲突并帮访客顺手调到可行的空闲档期，避免把带档期冲突的方案带进正式咨询单。支持重置回默认测算配置。

5. **工作台反悔回退与合作咨询单提交**
   - 访客在一边增删对比项目、一边调整排期配置比价时，希望能随时撤销或重做刚才的工作台操作（支持界面按钮与常用键盘快捷键）。
   - 确认意向后，支持将当前已选对比项目与排期测算方案一键带入下方合作咨询表单；填写姓名、回复邮箱与合作需求留言（10～500 字）后提交接口，生成带回执单号的咨询摘要并提供一键复制留底。
   - 页面显著位置请保留演示说明与待替换演示邮箱提示；收藏、对比、排期配置、主题偏好及未提交的表单草稿在刷新页面后不要丢失。

## 二、平时逛同类网站最让我头疼的四类槽点

做交互细节时，请特别留意别让访客遇到下面这些糟心体验：

1. **手快连切时页面抽风或张冠李戴**
   改搜索词、切分类、调排期或者连点下一篇文章时，有些网页要么整块突然清空闪一下再弹出来，要么半秒前慢吞吞发出去的旧请求晚一步回来，反而把刚切好的新内容给顶掉了。
2. **来回翻找丢位置、空手而归没出路**
   筛好分类往下滚了一半点开详情，退回来又被弹回页面最顶部重翻；挑了几个方案对比却只有密密麻麻的纯文字看不出长短板；输错词或者条件卡死搜不出东西时，只冷冰冰摆一句“无数据”，让人不知道怎么退回。
3. **小屏手机上看长文和悬浮栏打架**
   长文里的宽表格、代码块和对比图一到手机窄屏上就把整页横向撑破，吸顶栏加底部浮动条占掉大半个屏幕，甚至把底下的按钮挡死点不到。
4. **反复试算与填表提交太脆弱**
   排期调乱了想退回上一步又怕把刚敲在输入框里的字给误撤了；先在留言框写了几句团队情况，点一下带入方案结果把刚写的字全冲没了；遇到网络偶发繁忙报错或者手快连点两下提交，要么辛苦填的内容全丢了、按钮卡死再也点不动，要么一下发出去好几份重复单子。
